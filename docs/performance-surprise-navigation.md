# Surprise me from the homepage

The owner requested both faster navigation and earlier image display in the
already authorized collection publication batch. The selected destination is
shared by the desktop/mobile links and remains stable once prepared. A late
discovery-index response cannot switch to an artwork whose image was not warmed.
Current/recent exclusions and the source-projected cute index are unchanged.

The homepage prepares one selected detail page after the initial selection/index
refresh. Pointer, keyboard focus and touch can prepare it immediately. This
optional same-origin request warms the existing root-and-renderer-bound server
HTML cache. Navigation always follows the normal real href; it does not await
fetch, copy prefetched HTML into the page, or bypass current-root verification.
Failures, timeouts and disabled JavaScript retain genuine navigation.

Only the selected page's own canonical primary ImageObject and matching original
img may provide image hints. Its SHA-bound CSS loading image may be warmed too.
Read the document in an inert template so unrelated images, scripts and styles
cannot run. Limit retained hints to two, warm at most two destinations per page,
abort replaced work, bound document size/time, and skip optional requests for
Save-Data, 2G, offline or hidden documents. No whole gallery or random pool is
prefetched. Full original sources, schema, downloads and artwork identities remain
unchanged. No paid API, new derivative, service worker or credential is involved.

Surprise initialization has a separate early module entry and does not wait for
sharing/menu tools. The earlier original-image CSS loading improvement applies
to the destination. Actual timings and synthetic nonblocking/security/lifecycle
tests are recorded separately; a controlled fixture is not a live speed claim.
