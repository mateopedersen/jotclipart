# Source-bound first-visit preparation

This software extension prepares canonical HTML and the existing Studio bootstrap JSON during an authorized content transaction. It does not create new artwork, change editorial copy, resize media, change public image URLs or replace the existing publication authority. It does not promise subsecond original-image transfer on every network.

## Publication lifecycle

The installed software contains a SHA-bound Node renderer bundle whose digest is part of the software ABI. Normal content and collection-prose preparation use those installed renderers after all canonical source projections have been updated. The independent sealer repeats the same preparation and compares the source receipt, complete candidate, manifest, object descriptors and bytes before issuing authority. Remote metadata byte/MIME readback, native validation and conditional activation remain required.

Prepared HTML currently covers the ten principal discovery/Studio shells, subject and collection pages, and at most 512 exact current Surprise Me detail addresses. Editors and other artwork addresses retain the canonical reader. The maximum is 1,536 optional HTML routes and 128 MiB of derived output; an oversized optional document or exhausted optional source budget retains the canonical path. These are acceleration bounds, not a new artwork or publication count.

Studio uses the existing canonical provider, the same maximum 500 records, protocol and transport snapshot. A bounded publisher-only search-map cache prevents repeated reads during preparation. Public request concurrency and byte budgets are unchanged.

A record is used only when the installed ABI and the authenticated canonical source binding match. The binding covers all six other facet digests and the collections facet with only the derived fields removed. A source or software change makes stale prepared records fall back before their body is read. Descriptor SHA/size, compressed size, streaming expansion size, decoded SHA, UTF-8 and root-slot checks remain mandatory. Corruption fails closed.

## Initial software transition

Use the existing sole publisher. Reconcile its latest signed root and complete accepted source capsules before compiling. Preserve all native originals, independent KEEP/rollback snapshots, earlier receipts and immutable software URLs. Do not run the old full-catalog deploy path against a newer data-only catalog.

The software-only Pages installation accepts only the exact preceding root/ABI. The presentation bridge then changes the artwork envelope revision and adds derived collections metadata; canonical artwork directories, artwork/topic records and media bytes remain unchanged. This is not a new content import or a new visual review.

The bridge uses scripts/catalog-snapshot/publish-presentation.mjs with prepare, publish or finalize. Preparation requires the complete committed source-hash set and the installed canonical renderer bundle. Publish uses normal staging, independent sealing and guarded activation. A durable activation intent is written before activation. If an interruption occurs after the pointer changes, finalize validates the exact current signed root and saved receipts, then performs read-only live verification and an atomic accepted-baseline append. It never repeats staging, signing or activation. A different current root rejects continuation.

## Verification and reporting

The live verifier records the first four normal canonical requests before warming the remaining routes. It preserves actual MISS/HIT labels and records timing, source header and native/public HTML hashes after strict root normalization. Both Studio aliases must return the same canonical JSON, fresh root, no-store and protocol Vary headers.

HTML/API verification is not the final browser or media result. Separately check fresh Chrome and WebKit sessions, navigation, search, Surprise Me, original-image decode, Studio/editor initialization and actual Image/PDF bytes. Record preview paint separately from full-original completion. Old immutable software must still return its original bytes for existing tabs. Preserve a verified source/Git/installed-runtime backup and report real public measurements, remaining canonical fallbacks and network limitations honestly.
